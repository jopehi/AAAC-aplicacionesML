# Lab Guidelines

## Minimal template for documenting a weak pattern

Use this structure when documenting a scenario:

```text
Scenario:
Weak practice:
Location:
Business purpose:
Expected log evidence:
Future detection idea:
Scope note:
```

## Scope note

Always make clear that:

- the application is a local teaching lab
- the code is intentionally weak for analysis purposes
- the scenario should not be promoted as production guidance

## Focus

Prefer documenting:

- what the application does
- what bad design choice is present
- what artifacts that choice produces
- what later defensive analysis can be done

Avoid documenting:

- exploit chains
- operational abuse guidance
- instructions meant to bypass real systems
